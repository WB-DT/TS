# QuoteFlow

## Run locally

1. Install dependencies with `npm install`.
2. Set `AZURE_DI_ENDPOINT` and `AZURE_DI_KEY` in `.env` for document analysis. Copy the database settings from `.env.example` as needed.
3. Run `npm run db:setup` to apply migrations and seed the local SQLite database. The server also performs this initialization on startup.
4. Run `npm start` and open `http://localhost:3000/login`.

Run `npm test` to verify migrations, seeded records, reporting views, status history, separation of duties, OCR edit auditing, duplicate detection, and quote-type numbering.

## Workflow

All quote data and files enter through the Rep quote request form. Quotes are typed as `Quote` (numbered `Q-000001`) or `MDM` (numbered `MDM-000001`), each with its own counter, chosen by a team selector on the request form. Managers see every submission in the Quote log; Quoters work from their Home queue and the Quote workspace, where they run OCR extraction on attached files, manage files, upload pricing reports, and price lines.

## Pricing

`pricing.js` replicates the company's Cross Reference Tool. Upload the Account price report, House account price report, and Costing report (`.xlsx`/`.csv`) in the quote workspace. See [docs/metrics.md](docs/metrics.md) for the plain-English pricing rules. Made-up sample reports are generated by `node sample-data/generate.js`.

## Templates and export

`templates.js` defines export templates (column key, exact header text, Excel column letter, source, formula, and `internalOnly`). `presets.js` holds UOMs, count words, note presets, and the default target margin. The quote workspace exports an Internal Excel (full template) and a Customer Excel (internal-only columns removed) via `exceljs`.

The demo sign-in accounts are listed on the sign-in page. Demo passwords are `demo`; they are held in `auth.js`, not in the database.

## Database

The application uses Knex repositories and migrations under `db/`, with `better-sqlite3` by default. Local SQLite data is stored in the ignored `db/quotes.sqlite` file. No Azure AI keys, SQL passwords, or other credentials are stored in the database.

To connect the same schema and repository layer to Azure SQL, set `DB_CLIENT=mssql` and provide `AZURE_SQL_SERVER`, `AZURE_SQL_DATABASE`, `AZURE_SQL_USER`, and `AZURE_SQL_PASSWORD` (optionally `AZURE_SQL_PORT`). The `tedious` driver is already included. Existing SQLite records need a separate data transfer when moving environments; the application queries, migrations, and reporting view definitions do not depend on SQLite-specific route code.

See [docs/data-dictionary.md](docs/data-dictionary.md) for all tables and columns, and [docs/metrics.md](docs/metrics.md) for reporting formulas.
